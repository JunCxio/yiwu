电脑与走棋建议补齐将帅两轮避险：移动、整备及首轮安全吃子后，会检查对手下一次行动能否在武斗前两轮确定击倒己方将帅；落点预览同步说明这类漏防风险。将帅选招先避开首轮必败，再比较两轮风险，不读取暗招。自然复现中，电脑改为调士挡线，避免把三血将帅移入确定败局；这项修正没有解决长局，也没有证明整体强度提升。规则、样式与存档格式不变。

电脑选招评分进一步对齐实际结算：任一方被击倒后，双方离场，剩余气势不再计为后续收益；本场继续时仍会考虑气势。该项修正没有改变伤害或卡牌数值，也不代表长局问题已解决。

0.6.74 已将选招说明与建议中的轮内气势和离场后的气势分开：第六轮或提前击倒任一方时，武斗结束，双方气势归零；攻击招式仍会消耗现有气势。伤害和培养牌数值不变。

标准电脑走棋现在会优先抓住进攻将帅的两轮确定胜局，交战预览也会列出所需首招，并提醒下一轮根据揭示后的状态重新选招。只检查两轮及全部公开合法回应，不读取暗招；普通交战仍不保证获胜。

新建标准棋局和快速对局时，默认配牌按双方旋转对应的位置分配；同等位置的同类棋子获得相同招式，双方预算不变。旧续局保留原配牌，重新分散配牌只调整所选一方；新记录保存具体棋子和招式，刷新及导出可准确重放。

0.6.71 已完成 192 局集中与分散配牌对照，全部自然结束。独立种子复测中，集中主力相对配对分散方案的得分差为快速局 −4.2、标准局 +4.2 个百分点，尚不能据此认定集中培养过强或整体平衡已获保证；最长一局仍有 482 次行动。具体方法与限制见[测试说明](docs/testing.md)。

武斗揭示结果、重看出招及撤回确认时，焦点先放在顶部标题，便于先阅读结果；标题用文字颜色提示焦点，不增加外框或下划线。进入下一轮、双人交接或取消撤回时，会把当前控件滚动到可见位置；请求选招建议后，焦点与画面一起进入推荐理由和风险区。按钮滚动定位也为焦点外沿及教学标记留出空间。

矮窗口及较矮的窄窗口中，武斗改为整体滚动，避免固定头尾栏挤掉招式或裁切锁定按钮；常规窗口继续保留固定底栏。可滚动查看全部说明与操作，也可通过原有入口返回选牌。揭示结果、重看出招及撤回确认会回到顶部；下一轮进入选招区域，教学仍定位到指定招式。

终局标题与上下说明之间各保留 18 像素间距，标题聚焦时以文字颜色强调，不增加外框或下划线；窄窗口的操作按钮另起一行，对局页面保持自然滚动。

普通武斗选牌后，锁定区也会提示本轮可能或必定获胜、判负、判和；推演区列出对应的公开合法回应和真实终局原因。判断按当前选招者的红黑阵营区分胜负，覆盖将帅同时阵亡与实际行动判和。只检查当前一轮，不读取已锁定暗招，也不保证后续安全；换牌和刷新续局后按当前选牌重建。

分步教学的选招推演按本课公开的固定招式展示伤害与本轮后的生命，便于对照揭示结果；正式对局仍显示全部合法回应的范围，不公开暗招。

支援教学完成调动后，键盘入口会跟随当前可操作的棋子；Tab 进入棋盘后，可用方向键选择交点、Enter 确认。刷新续局同样可继续使用键盘。

普通棋局中，标准电脑与选招建议在进攻对方将帅时，会核对能确保至迟下一轮获胜的招式，覆盖对手全部合法回应，并计入真实耗牌、减伤与气势变化。若本轮未结束，需按揭示后的新状态重新选择下一轮必胜招式。当前一轮的确定胜局仍优先；守方、普通目标和残局不套用这项保证，练习难度保持原有分布。16 组新旧配对对照的胜负与行动数相同，尚不能据此称整体更强、更快或培养平衡改善。

## 开始游玩

1. 初次游玩，建议在首页选择「分步教学」，学习克制、气势、撤回与支援。
2. 选择电脑对战或同机双人。电脑对战中，你执红方；可选练习或标准难度。
3. 选择快速对局、标准棋局或残局挑战，点击「开始游戏」。
4. 正式对局已准备好分散配牌，可直接开始，也可先调整。双方培养预算相同，每子最多学习两张牌。
5. 点击己方棋子和落点移动；交战时先看预览，再发起武斗。双方暗选招式，同时结算伤害。
6. 不清楚下一步时，可使用「提示一步」「选招建议」及其理由说明。

选中己方棋子后，误点无法到达的空位会保留选中，并说明走法；车、炮的直线路径被挡时，会指出挡路棋子及位置。误点不消耗行动，可继续选择合法落点或改选其他己方棋子。点击敌子仍可查看详情。

残局挑战显示当前关次。前两关成功后，可先复盘，再点击「下一关」并确认切换，沿用当前电脑难度；确认前取消或刷新仍保留原终局。最后一关成功后可返回首页选择其他棋局。各关仍可从首页单独选择，没有额外解锁或养成奖励。走棋建议与电脑会优先选择可确认的残局首轮胜局，核对指定主力、支援与保护棋子的实际条件，避免为追将或改用其他棋子吃子而错过完成目标的机会。仍需在武斗中选用能完成目标的招式。

残局走棋提示与电脑共用评分：先击败黑将会使挑战失败，因此不会把追击黑将计为普通站位收益。提示不再无视主力伤势而强制推荐进攻指定目标；三关初始局面仍优先主力进攻。建议只依据当前公开信息，不能保证残血或复杂残局通关。

残局交战前会核对指定主力、支援与保护棋子：用错棋子击败目标、缺少首关支援，或先击败黑将，都会明确提示风险。武斗窗口中的普通说明默认折叠，有风险时自动展开；选招时保留手动展开或收起的状态。说明只依据公开棋局和本场固定支援，不读取暗招，也不保证武斗获胜。

残局目标区显示剩余的双方棋盘行动；正在进行的整场武斗计一次。临近时限时，落点预览、整备确认和交战预览会说明本次行动的代价；最后一次行动仍可正常完成目标。交战预览也会提示临近无伤判和的风险，是否判和仍以本场实际结果为准。

落点预览、走棋建议和整备确认共用实际行动结果。移动、整备或跳过受阻回合若直接结束本局，只说明终局后果，不再描述结束后的调动、进攻或用牌机会；整备直接结束时会明确恢复的牌在本局已无使用机会。查看与取消不会执行行动，发起武斗仍待真实交战结果结算。

落点预览、走棋建议和整备确认会举例说明「首轮吃子风险」：若对手下一步进攻并使用所示公开可用招式，本子的全部当前可用回应均会导致首轮阵亡，而进攻子仍可存活。整备按恢复牌后的实际状态判断；提示不读取暗招，也不表示对手已经决定进攻。没有这项提醒仍可能在其他出招或后续轮次中失子。

标准电脑与选招建议在残局中核对本轮结算后的目标、支援、保护棋子和行动时限。有确定获胜招式时优先落实；有其他选择时排除必定直接失败的招式。击倒目标仍可能因缺少指定支援、击败者不符或保护棋子阵亡而失败，建议会说明本轮直接取胜、失败或判和的后果。只核对当前一轮，不读取暗招，也不保证后续轮次。练习电脑继续按招式类型随机选择。

电脑会先按真实规则核对撤回后的结果：撤回即可直接获胜时，两种难度都会落实胜局；直接失败的撤回不作为保命选择。标准电脑仍优先确认可直接击倒将帅的招式，撤回判和按和局评估。选招建议与撤回确认说明相同的后果；电脑撤回后会显示原因，刷新续局保留结果。

点击「主动撤回」后先核对双方生命、耗尽牌、气势清零及下一方行动，确认后才结算。撤回会直接结束本局时，提前显示胜负或判和原因；残局还会显示撤回后的剩余行动。返回选招、按 Esc、回首页或刷新会取消未确认撤回，保留已选招式与已锁定暗招，不消耗行动。

继续武斗时，键盘焦点会回到原先选好的招式，必要时将该选牌及边框滚动到可见位置，方便核对后再锁定。同一步骤中的换牌、查看建议和撤回确认继续保留相应操作焦点；选中招式与实际锁定出招仍是分开的操作。

武斗选招在各类窗口中统一使用紧凑对峙栏，避免中等宽度仍显示完整角色而挤占招式区域；较矮窗口继续按原有规则收起待机画面，揭示后恢复完整像素演出。各类窗口均可在推演区点击「返回选择招式」回到原选牌；窄窗口的固定底栏另有「返回选招」，无需滚动到长说明末尾，也可从对手配牌直接返回。跳转不会锁牌或结算。选招时的交锋记录放在推演之后，结果页仍可先查看记录。

选好招式后，锁定区显示本轮结算后双方生命范围，并区分本子可存活、可能阵亡、必定阵亡。范围覆盖对手当前全部合法招式，计入实际伤害和剩余生命；这是所选招式的结果范围，不是胜率，也不表示对手已选哪一招。伤害同时结算，击倒对手仍可能自身阵亡。换牌时即时更新，刷新后按原选牌重建；同机交接、揭示结果及撤回确认中隐藏，固定教学继续使用课程指引。

手动选牌后，推演区会列出哪些公开合法回应会完成挑战、导致失败或判和，并显示真实终局原因；结果和原因相同的回应合并展示。换牌即时更新，不需要先请求「选招建议」。未列出的回应仅表示本轮不会直接结束挑战，不表示后续安全；说明不读取已锁定暗招。

残局选招还会提示本轮可能或必定完成、失败、判和。即使棋子存活，也可能因击败者不符、支援不足或耗尽行动次数而使挑战失败；这类风险会在锁定前显示。预估按当前所选招式与对手全部合法回应逐一结算，不读取已锁定暗招，也不推演后续轮次；没有成败提示只表示本轮尚未直接结束挑战。

培养牌不可用时，选招页与对手公开配牌会说明本场状态和具体条件，例如本兵尚未过河、哪方有几名支援，或守方不能使用借架。耗尽、满气势的原因优先显示。交战预览列出全部支援棋子的名称与路、线位置，支援输出最多加 2；支援在开战时固定，不能在武斗中调动。

交战预览新增「首轮判断」：列出可确保击倒目标并存活的招式，或提示守方能确保反杀的具体招式。判断使用双方当前全部合法招式，计入支援、克制、减伤和耗牌，不读取暗选，也不保证后续轮次的胜负。走棋建议使用相同说明；标准电脑会优先落实已确认的首轮存活击倒，练习电脑保留原有选招分布。

移动或整备一旦按实际规则结束本局，电脑与走棋建议就依据胜负或判和评估，不再计算结束之后的追将威胁、整备加分或重复惩罚。这能避免在已验证的优势局中，只为制造追将威胁而放弃存活吃子的机会；仍可接受有利的和局，并优先落实确定胜局。残局时限对移动和整备同样生效。普通交战仍使用现有近似估算，这次修复不表示整体电脑强度或对局速度已经提高。

普通棋局中，电脑区分将帅面前的实际风险与可确认的首轮反杀机会：如果存在一招能覆盖该进攻子的全部合法回应、击倒对手并存活，就不再仅因其走法覆盖将帅而给予完整的避险评分。将帅濒死、无法确认反杀时仍保留避险；残局挑战继续按原有目标判断。此修正与走棋建议共用评分，不读取暗招。212 局对照未证明整体对局更快，旧 405 行动长局仍未解决。

普通棋局的交战预览与走棋建议会补充「将帅漏防风险」：某些招式虽能在首轮吃子并保住进攻子，吃子后的落位却会让对手下一次行动确定击倒己方将帅。两条说明同时展示，避免把本子存活误解为整局安全。判断复用实际首轮结算，不消耗行动或培养牌；仍有阻挡、无法确认击倒或本局已结束时，不作此项确定败局提示。

将帅首轮吃子预览会进一步区分部分回应的漏防风险：列出危险招式和一个具体守方回应；若其他吃子招式面对全部合法回应都未发现同类下一手确定败局，也会列出供比较。没有完整替代时会明确说明。提示仅检查吃子后的对手下一手，不表示后续安全，也不预知暗招。

标准电脑与选招建议在将帅首轮进攻时，会比较多种可确保存活吃子的招式。若存在面对全部合法回应都能避开战后下一手确定击倒的选择，就排除有此风险的其他招式。直接获胜仍优先；守方反杀后轮到己方行动，不套用敌方立即进攻的判断。没有完整避险替代时仍返回合法选择，此检查不代表后续安全，也不读取暗招。

普通棋局的武斗也按实际终局评估：本轮已经获胜、判负或判和时，不再附加伤害、气势或耗牌收益。将帅参战时，若有其他选择，标准电脑与选招建议会排除面对对手全部合法招式都直接判负的招式；剩余选择仍可能被某些回应击败，不能视为保证存活。判断只用公开状态和合法招式，不读取暗选，练习电脑保留原有分布。本批对照没有证明整体更强或更快，部分棋局变长，完整范围见测试文档。

长局选招已减少状态复制开销。在本机旧长局样本中，平均计算耗时从 4.31 毫秒降至 2.02 毫秒；56 局候选重放的走棋、胜负、生命和耗牌与旧版参考一致。此项优化保持原有决策和推荐内容，不表示对局回合变少，也不能替代实体手机性能验收。

走棋评分现在只为实际受威胁的棋子查询防守支援，省去未使用的计算。在相同 43 个棋盘输入中，完整行动排序与得分保持一致；本机 Node.js 平均计算约减少 20%，Edge 平均为 2.82 → 2.65 毫秒，最慢单次未改善。56 局自然重放与旧参考一致。只减少计算开销，不表示电脑更强、对局回合更少或培养平衡已改善。

## 主要规则

- 保留象棋走法、阻挡、九宫和过河限制。不判将军或将死，将帅阵亡判负。
- 兵卒到底线后只能横移，不能后退或升变。落点预览、走棋建议和交战预览会提前说明这一限制；交战提醒以获胜并占位为条件，不表示已经吃子。
- 斩击克破势，破势克架势，架势克斩击。蓄势放弃本轮攻击，积累气势。
- 各类棋子基础生命和输出相同，培养用于学习招式，不增加基础数值。
- 站位可提供支援；伤势和培养牌消耗跨战斗保留。整备一张耗尽牌会占用一次行动，不回血。
- 武斗第二轮起，进攻方可在锁定招式前主动撤回，先核对代价再确认，保留伤势与消耗。
- 同一完整局面第三次出现，或连续 80 次棋盘行动没有损血，判和。棋盘显示判和进度；落点预览和整备确认会提醒该操作是否直接判和。
- 页面内「查看玩法」提供完整规则，伤害拆解说明各项加成和减伤。

武斗提供七类棋子的红黑像素角色，以及出招、受击、阵亡和撤回表现。双方锁定后才揭示动作，演出不改变伤害与出招顺序。刷新续局只显示静态结果。已揭示后可点击「重看出招」，撤回后可重看撤回；重看保持原有伤势、耗牌和回合。

交锋首轮揭示后即可展开「交锋记录」，查看双方每轮的实际损血、生命变化、气势和克制结果。最新轮次在前，累计损血只统计本场；记录不会显示尚未揭示的招式。

支持电脑对战及同机双人；当前没有联机对战。

终局的关次、标题与结束原因统一左对齐，各保留 18 像素间距，长文字随容器换行。标题获得键盘焦点时以文字颜色强调；按钮继续使用清晰的焦点框。桌面将结果标识、文字与操作分列，按钮区限制宽度并自动换行；宽度不超过 780 像素时按钮移到文字下方，对局页保持自然滚动。

对局页恢复自然纵向布局，内容超出窗口时滚动整页。终局总结、残局目标、教学指引和左右面板不再受一屏高度限制；棋盘保持原有比例与尺寸，不会因为上方说明变长而被压小。配牌列表、整备列表和战局记录保留原有局部滚动。首页和武斗窗口继续使用各自的紧凑布局。

桌面首页将对战方式与电脑难度并排，开始与玩法按钮并排；保存状态统一显示在页脚。1000 × 600 下，包含长残局说明与续局入口的已测首页无需滚动，按钮保持至少 44 像素高。较窄窗口仍使用单列布局；更长续局名称、系统缩放和小于 600 像素的高度仍可能需要滚动。

对局中的棋子详情优先展示已学招式，未学招式默认折叠，可按需展开查看。零培养棋子会提示四种基础招式仍可使用。换棋子、重新进入对局时，未学招式默认收起；同一棋子重绘保留展开状态。配牌阶段仍完整展示三张招式，方便比较和调整。长详情随页面向下延伸。

桌面武斗将四种基础招式排成一行，培养牌另列一行。选招时的像素角色缩为对峙栏，较矮窗口隐藏待机画面；揭示后恢复完整演出。窗口高度足够时，浏览右侧推演会暂时固定左侧招式，便于换牌；长推演、记录和对手配牌仍在正文内滚动，底部锁定与撤回操作保持可见。

桌面结果页将像素演出、交锋记录及电脑说明放在左侧，本轮红黑出招、实际损血和生命变化放在右侧。武斗结束时，结果标题先说明获胜、双方阵亡或达到六轮上限，再补充克制关系；实际损血仍以剩余生命为上限。伤害拆解和完整记录可按需展开，手机保留纵向排布。

## 续局与数据

最近一局自动保存在当前设备、浏览器和网站地址下。刷新后先进入首页，点击「继续本局」恢复。清除网站数据会删除续局，不支持跨设备同步。本机开发地址的续局不会自动转移到此试玩地址。

本标签页会暂存等待主续局写入的最新进度；刷新时仅在主续局仍与本页原记录一致的情况下恢复。另一页面已有新进度时，读取该页面的主续局，避免覆盖。此缓存随标签页关闭而清除，不能代替关闭前等待主续局保存完成。

游戏不收集或上传对局数据。若浏览器无法保存，会在页面中提示；请确认保存状态后再关闭页面。

遇到问题可在首页续局区、棋盘顶部或武斗窗口点击「导出试玩记录」，下载本局 JSON 文件。文件包含版本、模式、配牌与已执行操作，不包含尚未揭示的暗招、账号信息或其他网站数据，不会自动上传。导出不消耗行动，也不会改变电脑已锁定的招式。当前文件用于排查问题，不支持导入续局。

## 已知问题与反馈

电脑与走棋建议会在空位移动、整备以及可确保存活的首轮吃子后核对对手下一手的确定将帅击倒，降低可确认会漏防的行动的优先级；已触发判和或残局结束时，不再假设后续进攻。残局的确定获胜判断也按实际目标结算，提前击败黑将不算红方必胜。首轮吃子只在所有可确保存活的击倒招式、面对全部合法防守，都留下下一手确定败局时降低优先级；其余武斗和更长的走棋序列仍未覆盖。

电脑已改进重复追将与可确定的首轮交战评分，仍可能出现长局。本轮对照没有证实整体节奏改善，少量默认配牌样本还出现更晚判和。集中培养、分散培养和不同卡牌组合已做自动对照；这些结果不能保证真人对局的整体平衡，具体范围见测试文档。

请通过反馈入口说明关键操作、实际结果与预期结果，并附上导出的试玩记录。若无法附加 JSON 文件，可将文件内容粘贴到代码块中。截图和大致对局时长也有帮助。

[查看测试范围与限制](docs/testing.md)

[标准电脑近分随机范围试验](docs/standard-choice-trial.md)记录 60 局直接对战及 120 局自对弈对照。只选择最高静态评分虽缩短两份已知长局，但标准局独立复测得分更低，快速局自对弈合计变长；候选未采用，正式策略保持 0.6.93。

[配牌组合与随机起点分离复核](docs/allocation-factorial-0.6.93.md)补充 272 局及完整指令重放。标准兵卒对分散的九种搭配合计 38.5／72 分，各组合结果不同；快速默认配牌在交换随机序列后仍有执红偏弱的现象，两批执红得 22／96 分、执黑得 53／96 分。四组起点与少量默认对默认控制尚不足以定位原因，正式数值暂不调整，后续优先核查快速执红开局。

[0.6.93 培养方案交叉对战](docs/balance-0.6.93.md)包含当前策略的 240 局矩阵及 72 局特定对手复测。没有一种集中方案对所有对手占优；标准局兵卒集中对指定分散方案的差异仍需研究，快速默认配牌首批弱势未在新种子中复现。最长标准局仍有 398 次行动，未据此保证整体平衡或节奏改善。旧版数据保留在 [0.6.92 记录](docs/balance-0.6.92.md)与 [0.6.89 记录](docs/balance-0.6.89.md)。

## 本地运行

本项目无需构建或后台服务，入口为 `index.html`。下载后可直接用浏览器打开；保存能力取决于浏览器。也可在此目录启动任意静态文件服务器，例如已安装 Python 时运行：

```sh
python -m http.server 8000
```

然后访问 `http://localhost:8000/`。

已安装 Node.js 时，可运行 `node tests/computer-opening.cjs` 检查首轮判断及电脑决策，运行 `node tests/computer-ending-cards.cjs` 检查后续交战结束时的省牌、减伤与重复判和边界，运行 `node tests/computer-safety.cjs` 检查将帅安全与终局判断，运行 `node tests/computer-retreat.cjs` 检查撤回的直接胜负与判和，运行 `node tests/computer-combat.cjs` 检查普通武斗终局评分、离场气势与将帅必败招式排除，运行 `node tests/computer-state.cjs` 检查终局预演的完整状态与原局隔离，运行 `node tests/computer-two-round.cjs` 检查两轮将帅取胜、培养耗牌与提示边界，运行 `node tests/combat-help.cjs` 检查配牌条件、支援、吃子漏防与兵卒底线说明，运行 `node tests/challenge-flow.cjs` 检查残局目标、行动后果、切换与续局，运行 `node tests/piece-panel.cjs` 检查棋子招式分组与配牌、整备入口，均不需要安装依赖。

交战后将帅风险可运行 `node tests/combat-followup-preview.cjs` 检查，包含完整合法续局、红黑与进守、末轮离场、吃子落位、终局边界及暗招隔离，直接用真实结算对照提示。

刷新续局可运行 `node tests/autosave-pending.cjs` 检查，覆盖写锁排队、最新选牌、结算结果、跨页面冲突、写入失败、损坏缓存和旧请求失效。

气势预估可运行 `node tests/combat-force-preview.cjs` 检查，覆盖末轮、提前结束、培养与削势，并逐项对照真实结算。

教学选招推演可运行 `node tests/tutorial-preview.cjs` 检查，覆盖固定教学结算、查看不改状态，以及正式对局不读取已锁定暗招。
