# 0.6.104 协同攻将防守验证

旧版只检查对手移动后，该棋子自身能否攻将。红马移入炮线建立炮架、另一枚棋子移开挡线等配合，会让不动的棋子成为攻击者，旧筛选因此漏判。

共享检查改为枚举真实合法空位调动，先检查投影站位中所有敌子能否攻将，再执行真实行动，核对有效攻击、可靠首轮反杀与将帅的空位退路。实际调动或逃离直接判和时不虚构后续。原评分权重保留，两种走棋难度与走棋提示同步使用；战斗规则、培养牌、武斗选招、CSS 和续局格式不变。

检查仍只在己方将帅当前没有有效受攻、至多一条安全空位退路且轮到对手时启用。没有穷举其他棋子的完整解围，也没有把逼帅风险记作确定将死。

## 已知病例与单步对照

0.6.103 培养矩阵中的两份分散配牌对兵卒集中病例，在第30次行动前共享以下站位：黑将在 `(5,0)`，红炮在 `(5,7)`，红马在 `(7,5)`。炮线尚无炮架，黑将当前不受该炮进攻，仅有 `(5,1)` 一条安全空位退路。旧版选择将黑卒由 `(8,4)` 移到 `(8,5)`。随后红马到 `(5,4)` 建立炮架，红炮既可攻将，也覆盖了唯一空位退路；红马自身不攻击黑将。

先固定旧策略，只替换第30次行动为黑将到 `(5,1)`，并保留原查询消耗的随机输入。两个控制均精确复现红方第33次行动获胜，替换后分别在203、208次行动因无伤判和。四场共602条指令独立重放通过。此诊断证明提前移将能够改变这两份旧病例，不证明统一强制移将有效。

新版在同一第30步站位推荐黑车从 `(6,8)` 到 `(6,5)`，挡住红马跳到 `(5,4)` 的马腿。实际浏览器自动走棋与提示均核对一致；提示仅展示落点与理由，不执行行动。

## 回归检查与旧测试修正

- 两份完整合法历史及红黑旋转，核对8条真实压力分支、全部合法行动旋转评分、两种难度、输入不变、可靠反杀、调动与逃离直接判和。
- 独立构造移开车线挡子的站位，验证移动者不攻将、静止的车成为攻击者，由同一检查识别。
- 旧版在新增测试的具体排序断言失败，候选通过。
- 两份旧测试中名为 `safe` 的对照也能被调马建立炮架。单出口旧例在黑炮到 `(4,2)` 后，红马到 `(5,4)` 让红炮攻将；零退路旧例在红帅到 `(3,7)` 后，黑马到 `(3,6)` 让黑炮攻帅。两条真实分支及红黑旋转均保留为断言。
- 原直接进攻分支保留，并用残血炮可被可靠首轮反杀的边界状态核对风险区分。第一份旧例在遭配合攻将后还有其他棋子可解围，测试明确保留这一事实，避免把本检查解释为将死搜索。

全部33个仓库脚本、31项规则和143项界面流程通过。正式入口与本机镜像字节一致，规则脚本、除共享辅助函数外的电脑脚本、武斗策略与CSS逐字核对不变；界面脚本只改版本与提示范围文字。
