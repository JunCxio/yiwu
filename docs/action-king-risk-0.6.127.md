# 撤回与整备后的将帅威胁

0.6.127补齐行动确认中的信息遗漏，并修复短屏撤回确认按钮超出窗口的问题。本轮没有调整战斗规则、伤害、培养预算或电脑评分。

## 修复的问题

在一场标准快速局的第35次行动前，红炮可以隔着红帅进攻黑车。红炮交战后撤回，黑车仍可进攻18血红帅，但红炮本身不会被该黑车直接进攻，红帅也不是下一手武斗两轮内的确定败局。旧版撤回确认和撤回建议因此可能不显示将帅风险。若红炮已使用借架，撤回后再轮到红方整备，原整备确认同样没有说明这项威胁。

新查询只查看行动实际结束后的公开站位，列出仍可向己方将帅发起武斗的敌子名称和位置，并明确“能发起武斗不等于能击倒将帅”。撤回原有的两轮确定败局提示优先保留，撤回棋子本身的追击风险继续单独说明。行动直接判和或结束时，不再假设对手还能继续进攻。查询不执行行动、不读取暗招、不改变耗牌、伤势或续局格式。

窄屏原有武斗内容可以整体滚动，但长撤回确认会将底部按钮推到可视范围外。本次只在短屏撤回确认期间固定可用高度，使说明正文内部滚动、底部操作保持可见。退出确认后恢复原有武斗滚动方式。

## 验证

可运行：

```sh
node tests/action-king-risk.cjs
node tests/retreat-risk.cjs
node tests/challenge-flow.cjs
```

新增测试和夹具随仓库提供：两份完整合法走棋历史分别复现撤回和整备，包含红黑换色共4组；覆盖满血将帅受攻、威胁名称及坐标、无威胁边界、直接判和、原低血量警告、两处撤回说明一致、不读取暗招和输入不变。新增测试在0.6.126首先因缺少满血将帅威胁而失败；修复后49个程序检查脚本通过，包含143项界面流程。已有测试只增加共享函数的加载依赖，没有改动原断言。

独立Edge无头浏览器以临时本机来源运行16个流程：1366×768、390×844、320×568、740×360，分别覆盖电脑对战、同机双人的撤回和整备。核对取消、刷新、继续本局，操作数量不变，待选招式及电脑已锁定招式保留；所有尺寸没有横向溢出或页面错误，确认按钮位于窗口内且高度至少44像素。短屏退出确认后恢复整体滚动。已人工查看桌面、320像素及横屏截图，没有接触线上用户续局。

规则与电脑两个脚本和0.6.126逐字相同；三个脚本可编译，存档格式仍为1。本轮只改界面查询、两处调用、短屏确认样式及版本文字。

## 围帅诊断与未解决的问题

本轮还核查了同一败局第37次行动：原电脑选择调士增加支援，另一分支让红帅主动进攻相邻黑车。主动进攻可在第二轮起撤回，这不等于之后脱离威胁。

从同一公开局面出发，用256组新种子配对比较两条分支；两边均消耗本方走棋查询，再替换为指定行动，之后由现有标准电脑执行下一次棋盘行动及完整武斗，在本方重新取得行动权或实际终局时停止。

| 分支 | 256次中将帅阵亡 | 平均将帅剩余生命 |
|---|---:|---:|
| 调士支援后防守 | 92 | 3.8633 |
| 将帅主动反击 | 119 | 3.0469 |

旋转换色逐条复核得到相同结果，不另算独立样本。这只是一个局面的有限诊断，不能用来推断完整对局胜率，也不支持统一奖励将帅反击。所用512个种子与明确核查的3820个历史使用或预留值无重合，不是对全项目历史的穷尽排重。

另有只结算一场武斗的局部试验，随机查询流程与上述两次棋盘行动试验不同，不能把两批逐样本相减。两次试验连同换色共2048份诊断轨迹、11680条已执行命令，已另按真实规则重放并核对完整终态，未再次计算全部随机选招。完整诊断原始记录在本机工作目录留档，本说明没有提供完整公开复现包。

本轮没有重新进行完整对局矩阵、真人、实体手机或其他浏览器验收。单子主导、长局和集中培养平衡仍未解决；风险说明用于辅助判断，不保证后续安全或更强棋力。
