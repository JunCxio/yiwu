# 同分走法的静态路线试验

为减少电脑往返调动，本轮比较同分走法到合法进攻入口的最短路线。修正版主批通过，但独立复测中三组平均行动数增加，两组换色对战低于半分，因此不采用。正式游戏与本机镜像保持0.6.136；本次只公开试验记录。

## 诊断与候选

在[上轮32场现版记录](team-role-0.6.136.md)中，固定其他棋子的位置，按真实走法与阻挡计算某子到可合法进攻任意敌子的最少空位移动数。和局尾段450次车马炮兵空位移动中，120次无路线、76次已经能进攻、164次路线变短、70次不变、20次变长。该距离不判断目标价值、途中安全、交战收益或对手回应。

仅5次存在同一棋子的同分近路，其中2次已连续79次无伤，空位移动直接判和。其余3处各强制一次同分近路后，对局长度均未改变：385→385、325→325、325→325。这不支持仅凭静态距离就认定整局能缩短。

初版在不同棋子间比较路线，会混淆将帅飞将与兵卒发展。58个脚本任务中，旧 `computer-score-precision.cjs` 失败，初版弃用，原检查未改。

v2只在同一枚车、马、炮、兵的最高同分空位走法中筛除绕路。128场主批中四组自弈平均均缩短，但练习完整局直接对战仅7.5／16分，未通过。进一步发现删减选项会改变全局选子概率：索引102、命令索引184的首次分歧中，同一随机数使原版选择0.095分红兵走法，v2改为0分红帅走法。原版404次行动和棋，v2在318次行动红负；不能把全部后果归因于这一处选择。

v3保留原随机槽位，只将某子的较远同分走法映射到原集合内同一棋子的同分近路，逐槽保持棋子、行动类型和评分精度，仍调用一次随机数。提示与电脑共用候选选择。原评分、近分边界、练习前三截取、开战、整备、直接终局、残局、武斗策略、规则、培养、CSS和续局格式保持。所有候选均未进入正式游戏。

## 前置检查

v2与v3各通过57个既有仓库脚本及143项界面流程，共58个脚本任务，正式旧测试与断言未改。最终专项包含135项距离核对、覆盖七类棋子，24份候选池检查、12次替换、8处直接终局保留；开战、整备、残局、无路、随机调用和输入不变检查通过。

两版分别串行测量139份固定走棋查询，各预热3次后交替测量11次。v3最大中位45.386毫秒，全部达到预定中位50毫秒、冷查询与热单次100毫秒、开局额外中位不超过5毫秒条件。原始状态与全部样本保留；这是本机Node计时，未测浏览器或实体手机性能，不代表候选提速。

## 冻结门槛与完整对照

每批包含标准／练习、快速／完整四组，各8根；每根运行原版自弈、候选自弈及换色直接对战，共128场。双方预算相同，默认培养对分散配牌，未覆盖集中培养完整交叉。每组须直接得分至少8／16、自弈平均及最长行动均不增加，且至少一组节奏改善。全部必须自然终局、完整操作与终态可重放；采用前还须独立32个新根按同门槛确认。2,000次行动和14,000条命令仅为中止保护，超限不能算和棋。

## 复核与限制

在仓库目录运行：

```sh
node docs/data/verify-piece-route-trial-0.6.136.cjs
```

脚本只依赖Node标准库，核对压缩数据和四份源码、补丁范围、规则与样式一致、三批冻结种子、输入分配与采用门槛；合法重放384场，重算全部终态和分组结果，并重现v2选子概率缺陷及v3逐槽保留。另重算原始计时摘要，核对专项和回归结果。它不重跑全部电脑选择、专项、回归或性能计时。后续入口变化时，需传入本报告哈希指定的0.6.136入口路径。

压缩数据的 `files` 保留各版源码、诊断、计划、报告与运行脚本，`batches` 保留全部对局。工作目录脚本依赖原项目辅助文件，独立复核请使用上述公开脚本。失败候选没有进入浏览器、刷新续局、真人或实体手机验收，也未追加新批或缩窄到单一通过模式来改变采用结论。

静态近路不保证抵达有利目标，也不计对方移动。本次结果不足以支持通用替换同分走法，后续应先核查端点的交战价值、途中安全与对手回应。长局、高和棋及集中培养的完整平衡问题仍未解决。
