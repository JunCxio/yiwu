# 0.6.103 将帅零退路时的下一手逼帅风险

本版让电脑和走棋提示区分两种当前都安全、却没有安全空位退路的站位：对手下一手能够通过空位调动进攻并封住退路，以及没有这种调动。原先两者可能同分，导致电脑随机移向更容易受压的位置。修正沿用已有的轻度退路代价，没有新增配置或改变战斗数值。

基线为 0.6.102，提交 `e33b2d37c33d12709897497620e752aa534aa6e7`。正式入口 SHA256：`db439053bb1a4a8c9b986f3ed52e6ea47fc0181c8fdcaf0b59ac88cb7968bb0e`。

[计划、完整指令、逐子统计与验证数据](data/king-zero-exit-0.6.103.json)，SHA256：`d9208b8de92de8687a4f2b52f5a887e87d3bea679b60c75b0cb524924a777427`。

## 问题与修改

[0.6.102 培养矩阵后的旧病例核查](balance-0.6.102.md)发现，第 55 次行动前，红帅从 `(3,8)` 移至 `(3,7)` 或 `(4,8)` 后，当前均不受有效进攻，也都没有安全空位退路。只有后一个落点可被黑车移至 `(6,8)` 或黑马移至 `(3,6)` 后再次进攻并封住空位退路。坐标为代码中的零起点坐标。

原评分以同一个条件处理“零退路”与“单出口会被封住”，零退路时没有再区分下一手的压力。现在保留零退路基础代价，并在轮到对手、至多一条安全空位退路且已有检查确认存在下一手逼帅封锁时，再计一次相同代价。单出口的原代价不变；既有检查继续核对真实合法调动、阻挡、炮架、反杀及直接判和。

该病例的两个移帅行动原分数均约为 26.04；修正后 `(3,7)` 保持 26.04，`(4,8)` 降至 21.84。固定随机输入 0.75 时，标准电脑改选前者。共享评分影响两种电脑与走棋提示，提示只给建议，不执行行动。武斗选招、规则、培养牌、CSS 和续局格式保持不变；提示文字同步说明检查范围。

这是有限的空位压力判断，不是确定将死，也没有搜索其他棋子的完整救援或更长序列胜负。

## 回归与界面

新增 `tests/computer-king-zero-exit.cjs` 和完整合法历史 fixture，覆盖原色及红黑旋转、四条实际压力分支、全部合法行动排序、两种难度各五个随机输入、查询不改状态，以及己方行动、无伤和重复直接判和。旧版两组均在风险排序断言失败，修正版通过。全部 32 个仓库脚本、31 项规则和 143 项界面流程通过；正式入口、实验候选与本机镜像字节相同。

Edge 在 1366×900、390×844 下分别核对标准提示、练习提示和实际标准电脑行动，共六个场景。原病例两种提示均推荐红帅移至 `(3,7)`，不消耗行动；电脑在既有防线病例中实际调炮。各场景刷新后 90 格棋位、生命和牌数显示一致，无横向溢出、警告或错误。测试使用独立本机端口和合法续局，没有操作原站存档。

用户截图中的结算标题边框已在此前版本移除。本轮确认线上 CSS 与本机相同，再以相同失败残局核对 1912×866、1366×768、390×844、320×568：标题获得焦点时无外框，上下间距各 18 像素，按钮无重叠，无横向溢出。没有为已修复的问题重复添加样式，对局页继续自然滚动。
