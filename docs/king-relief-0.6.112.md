# 0.6.112：受困将帅的反击解围

普通交战的平均伤害预测，过去只处罚己方将帅新增的受攻风险，不奖励解除已有风险。移动与整备则通过完整站位差值比较，会计入风险降低。因此，预计能吃掉攻击者的反击可能低于仅增加支援的调子。

0.6.111的一份快速局中，红帅在第65步没有安全空位退路。原评分认为红士可在支援下存活并吃掉黑车，却给反击8.3分、调炮11.045分，随后红帅在第66步阵亡。炮的支援确实成立，问题不能解释为炮架错误或培养牌过强。

## 最终修改

普通非将帅交战预计降低己方将帅当前受攻时，先检查真实合法的空位移将：有可脱离当前受攻，或直接结束本局而不判负的退路时，保留原判断；没有这种退路时，加入预计降低的当前受攻成本。原有新增受攻、封路风险、可靠首轮终结、两轮残血吃子和确定胜局检查继续保留。

移将判断复用原有攻将评分中的规则结算，抽为内部函数；一次排序内按需缓存己方退路判断。两种电脑难度和走棋提示共用修改。没有改规则、卡牌、伤害、培养预算、武斗选招、CSS或续局版本1。已保存的历史与暗招继续按原记录恢复，后续电脑走棋使用新排序。

这是平均伤害启发式，预计吃子不等于保证吃子。检查的是将帅空位退路，不是全部挡线、支援或完整武斗搜索。

## 单步诊断与回归

另用原版重算66步病例，只把第65步调炮替换为红士反击。两场精确共享前78条命令，第65步原查询照常运行并消耗随机输入，之后继续调用原版电脑。控制为66步黑胜，单步替代为223步和棋；两场362条命令、289次走棋和88次出招选择核对通过。该结果仅说明一次解围有价值，不是最终候选的318步结果，也不是新的独立开局样本。

新增测试包含红方第65步、黑方第194步的合法完整历史，以及两者红黑旋转共4份状态；检查没有安全空位退路、不是首轮确定吃子、两难度40次固定抽样选择反击、全走法旋转分数一致及查询不改输入。旧版在反击检查处失败。已有满血目标安全移将、协同防守和确定吃子测试继续通过。

正式39个仓库脚本、31项规则与143项界面流程通过。Edge在1366×768、390×844共六条流程检查两种难度实际反击、提示只查看和刷新不重复结算，无横向溢出或控制台警告错误。12份开局、中盘、长局及问题局面，三遍预热、十轮交替各120次排序，平均2.665→2.763毫秒；单次最大11.6→18.1毫秒。48次原站位评分比较完全一致。这是本机脚本查询开销，不含渲染、动画、玩家操作或实体手机。
