# 0.6.102 走棋评分精度

本版修正电脑和走棋提示中，浮点评分尾差改变同分排序、近分边界被误排除的问题。相同精度的分数按原合法行动顺序排列，电脑仍在原有近分范围内随机选择。培养预算、伤害、牌效、武斗选招、样式及续局格式保持不变。

## 问题与修改

[0.6.101 培养矩阵](balance-0.6.101.md)中的移牌对照发现，第 8 次行动前，双方棋位、生命、预算与合法行动集合相同，只把黑车两点移给黑士。所有行动评分保留小数点后九位时相同，最大原始差仅 `7.105427357601002e-15`。原代码直接按浮点差排序，导致两个近分走法换序；相同随机输入 0.75 因而选择不同棋子。近分筛选直接做小数减法，也会将恰好位于 0.06 或 1.2 边界的走法误排除。

现在排序和边界均使用 `Math.round(score * 1e9)` 得到的整数单位。比较器直接比较整数，因此具有传递性；没有使用“差距小于某值即相等”的不传递比较器。原始评分值和权重保留，只有比较精度明确为十亿分之一。同分保留 JavaScript 稳定排序下的原合法行动顺序。标准电脑仍取最佳分数差 0.06 以内的走法；练习电脑仍取差 1.2 以内的前三项。提示仍采用排序第一项，不自动执行。

两处比较共用同一个内部转换，不增加公开接口、依赖或设置。对局中的实际分数远低于整数安全范围；该约定只用于游戏内部走棋评分，不改变真实生命或伤害结算。

## 回归与界面

新增 `tests/computer-score-precision.cjs` 和完整合法历史 fixture。原色、旋转后的移牌局面核对全部合法行动的同分顺序、两种难度、五个随机输入、查询重复与状态不变；近分单元检查覆盖正负分、零分、恰好边界、明确超界、练习前三项、空走法和错误阶段。测试只在独立上下文替换边界用的评分输入，生产游戏没有测试入口。旧版在四组检查中均失败，修复版通过。

正式入口与镜像字节相同。全部 31 个仓库脚本、31 项规则和 143 项界面流程通过，既有确定胜局、将帅防线和武斗测试保留。源码比较确认规则、武斗策略和 CSS 相同，界面脚本仅更新导出版本号。

Edge 在 1366×900、390×844 中分别核对实际电脑走卒、原培养与移牌后的走棋提示，共六个场景。固定随机输入 0.75 时电脑走黑卒至 9 路 6 线，两种配牌的提示均为黑车至 8 路 8 线。提示不改变棋位、生命与耗牌，刷新后 90 格棋位及棋子显示一致。测试使用独立本机端口和合法续局 fixture，没有操作原站存档。一次连续测试在刷新尚未完成时读取了首页中的棋盘，补上页面加载及对局可见的等待后重新核对通过，没有因此修改游戏续局逻辑。
