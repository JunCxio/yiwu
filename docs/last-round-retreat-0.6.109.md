# 0.6.109 末轮无收益蓄势止损

一份快速局在第126次行动、第六轮武斗时，1血黑卒进攻4血红兵。原标准电脑对基础蓄势分配约35.2%的概率、对撤回分配约64.8%；记录中实际蓄势，被红兵斩击击倒，红兵没有损血。武斗已是最后一轮，新增气势马上清零，红兵又没有可用培养牌可消耗。撤回则保留黑卒，通过现有防线检查且不直接结束整局。

## 修改范围

标准电脑与选招建议共用 `combatPlan`。仅在普通棋子交战第六轮、本场已有伤害、对手全部合法选项都是基础招式、撤回不产生即时终局且现有防线风险为0时，把保留下来的基础蓄势概率转给同样保留下来的撤回。先执行原有防守、可靠吃子和省牌判断，再处理这次转移，其余招式权重不变。

不能先删除基础蓄势再省牌：标准局另一份真实历史中，红相的 `elephant_store` 原可用基础蓄势替代；先删除基础招式会让这张培养牌重新残留。最终实现将止损放在省牌之后，并为两份历史保留回归。

这项处理不套用于提前轮次、将帅交战、残局挑战、对手有合法可用培养牌、没有既有伤害，或撤回直接判和等终局。练习电脑出招和棋盘评分未改，守方计划没有加入这次转移。手动蓄势仍合法；旧续局已锁定的电脑暗招继续原选择，不在恢复时重抽。规则、卡牌数值、CSS和续局格式保持不变。

## 验证

`tests/computer-last-round-fixture.json` 保存164条合法命令至真实病例，以及132条合法命令至省牌顺序病例。撤回测试由6组增至10组，覆盖红黑旋转、真实结算、概率归一、输入不变、提前轮次、对手培养牌、无伤计数、即时判和及撤回后确定丢将的边界。部分边界通过修改构造状态验证，不作为额外真实对局。原版在病例断言失败，初版候选在省牌顺序断言失败，最终候选全部通过。

```text
node tests/computer-retreat.cjs
```

36个仓库脚本、31项规则和143项界面流程检查通过。另按原命令核对0.6.107矩阵536场、167,929条操作，完整终局哈希一致。977个满足宽筛选条件的末轮输入中，903个发生基础蓄势到撤回的概率转移，只有1次原记录实际选择了基础蓄势。受查守方计划与原版一致，除转移外的权重差在 `1e-10` 容差内。这是历史输入核查，不是536场新版对局，也不代表903个错误操作。

最终冻结源码以0.6.108提交 `4ea4472125d77138a33a61df2ec72ebafcf07b70` 为基线。旧病例各跑原版与新版，共2场；快速、标准各4组新根，每根运行原版双方、新版执红、新版执黑及新版双方，共32场。同根四场共享配牌和随机序列，不能当作独立样本；新种子与最近536场矩阵无重合，但未检查项目全部历史种子。初版候选另有34场试跑，不计最终样本。
