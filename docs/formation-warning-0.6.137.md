# 0.6.137 重复阵形提示

走棋建议和落点预览现在会解释己方阵形往返风险，避免把「完整局面还没重复」理解为「这一手没有在往返」。这是一项说明补充，没有改变电脑评分、走法、武斗、培养、判和规则或页面样式，也不表示对局已经缩短。

正式入口与本机镜像SHA256均为 `c51d788d89fa8be37df6fc66d2f67bc58158f764c68cceae4334cb4a754f7c8c`。原版入口来自提交 `dcc005fe10c6cbc929fcfff90c271fdb94e509dc`，SHA256为 `812c41ee1b1edbe63fb2b930ec1593ca89123b65edfb816131fa2ddd40e4fe16`。

## 提示与状态

入口沿用「提示一步 → 查看理由与风险」和「开启落点预览 → 选择合法空位」。真实规则预演后，如果仍是棋盘阶段、已经交给对手行动、完整局面此前未出现，而己方阵形曾出现，则加入：

> 此步会回到己方曾出现过的阵形（此前 N 次），继续往返仍会累计无伤行动。对手位置可能不同，完整局面判和仍按双方全部状态判断。

原有电脑统计忽略对手位置，但仍保留对手身份、生命、学牌及耗尽状态，并保留己方全部棋子位置与状态、行动方。新提示复用这一统计。该计数仅描述历史，不能代替完整局面判和；完整局面第二次出现时沿用原说明，实际终局优先显示终局结果，不叠加本次提示。

内部抽出原有阵形历史统计，排名继续按原计数、每次3分且最多计两次进行惩罚；新增只读查询 `YiwuComputer.formationRepeats(state, next)`。建议与预览不会执行走棋、消耗行动或读取未揭示暗招。续局仍使用格式1和原命令重放，刷新后重新计算提示，不新增存档字段。取消预览保持棋局，确认后才按真实规则执行并保存。

## 发现与核查

从0.6.136培养矩阵选两种难度、两种棋局各自最长局，并列取输入顺序最早者，检查各自最后80次棋盘行动。四份旧历史共2,763条命令、320个尾段状态，40次行动回到己方旧阵形，但完整局面此前未出现且没有立即终局：标准快速33次、练习快速7次，两类完整局0次。仅8个尾段状态有进攻入口，原最高进攻评分均为负；这不能证明不存在更好的多步选择，也不能支持直接调整牌值。

34组新增专项通过，覆盖两份完整合法历史及红黑旋转、建议和预览、无重复、完整局面第二次及第三次、无伤终局优先、历史次数实时变化、生命／位置／学牌／耗尽状态边界、恢复一致、输入不变和暗招隔离。

最终58个仓库检查脚本（57个既有脚本加新增专项）与143项界面流程共59个任务全部通过。所有既有测试及夹具哈希保持，三段入口脚本解析通过，发布入口与镜像字节一致。

四份旧历史的320份完整排名逐项与原版精确一致；2,663个空位移动／整备预演与独立规范化算法的计数一致；四个尾段首状态各按两难度、五个固定随机值核对，共40次电脑选择一致。全部完整终态与原记录一致，查询未修改输入。没有新增平衡对局，也没有独立重算四场中每一手的全部电脑选择。

## 显示、操作与耗时

Edge使用独立本机测试源装载旧格式1续局，未触碰正式站续局。在1366×768核对提示和预览，在320×740核对长文字滚动、键盘到达确认／取消，未发现横向溢出或文字覆盖。窄屏两个操作按钮均高44像素，正文仍需滚动。取消后棋子及无伤7／80保持；刷新后提示重现；确认一次移动后仅交接一次行动、无伤变为8／80，再刷新仍恢复相同位置与计数。没有记录到页面警告或错误，临时视口已还原。

Node.js v24.21.0分别对四个尾段首状态和两种开局按两难度测量12组走棋查询，另对两份提示夹具测量建议／预览4组。每组先各测一次、预热3次，再交替顺序各测11次。沿用中位不超过50毫秒、热单次及首次查询不超过100毫秒、开局额外中位不超过5毫秒的预算，16组均通过。现版走棋查询中位约1.83～34.92毫秒，首次最高50.92毫秒；提示／预览中位约1.33～1.81毫秒，均略高于原版。该结果只覆盖这些固定Node局面，不代表提速或浏览器、手机性能。
