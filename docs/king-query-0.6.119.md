# 0.6.119 协同逼帅查询提速

电脑评估一次移动时，需要检查对手是否能调动棋子，令己方将帅受攻且没有安全空位退路。本轮减少该查询的无效枚举，保留原有策略、评分、行动顺序和随机采样。

## 修改与影响范围

入口仍是 `rankedActions → position → kingMobilityCost → advanceTrapsKing`。新预筛只保留移动者和静态走法形状可能覆盖将帅的敌子；车、将之间超过一枚挡子，或炮之间超过两枚挡子时，单次移动无法建立相应进攻。没有静态潜在攻击者时，进一步排除单轴距离超过四格的短程调子。

预筛后仍逐一核对真实合法走法、支援与可靠反杀、行动后的判和，以及全部将帅空位退路。移动者可能为另一枚炮建立炮架，或移开车线挡子，因此不能仅检查移动者自身。查询不改动输入；没有新增接口、状态、持久化字段、依赖或异步过程。

规则脚本、CSS、界面逻辑除版本标识外逐字相同，培养牌与生命、伤害数值不变。导出记录版本更新为 0.6.119，续局格式仍为 1；正式入口与本机镜像一致。

## 测量

先用 Node.js 自带 CPU 采样定位：标准开局的协同逼帅扫描约占排序总采样时间的一半，大量时间用于重复走法几何检查。该采样用于定位，不代替浏览器计时。

两环境各使用相同的 11 个开局和旧局面，原版与候选交替运行。Node.js 每个局面预热两次、测量各 11 次；应用内 Chromium 预热三次、测量各 11 次。浏览器每次另外核对完整评分、排序和输入不变，计时包含结果序列化。测量时没有同时执行其他测试脚本。

| 环境与局面 | 原版中位 / 毫秒 | 候选中位 / 毫秒 | 候选最高 / 毫秒 |
| --- | ---: | ---: | ---: |
| 应用内 Chromium，标准开局 | 9.50 | 5.60 | 8.40 |
| 应用内 Chromium，快速开局 | 1.40 | 1.20 | 2.00 |
| Node.js，标准开局 | 86.13 | 47.32 | 51.48 |
| Node.js，快速开局 | 8.65 | 6.20 | 6.27 |

两个环境的 11 个局面均通过此前固定的性能门槛：中位不超过 50 毫秒，单次不超过 100 毫秒，开局额外中位不超过 5 毫秒。部分中残局略慢，例如浏览器 quick-209 的中位 4.1→4.4 毫秒，不能宣称所有局面都提速。浏览器结果来自本机应用内 Chromium，不能视为 Edge、其他设备、帧率或实体手机结论。

[全部原始计时、回归记录与复算摘要](data/king-query-0.6.119.json)同时记录实测候选和最终入口校验值；两者查询代码一致，仅版本标识不同。

## 正确性与流程

- 新增专项与不预筛的真实规则穷举比较 544 次双向查询，141 次存在实际压力，覆盖四种自然历史夹具及红黑旋转、256 份人工站位、短程距离、挡线、炮架、伤势、耗牌、判和和输入隔离。人工站位用于覆盖边界，不计作合法完整对局或平衡样本。
- 41 个可传入源码的仓库脚本，以及残局流程与棋子侧栏脚本通过。新增专项最初未正确读取不同夹具结构，修正测试读取后通过；没有因此修改候选游戏查询。另通过 31 项规则及 143 项界面流程。
- 用现版重新决策并结算原控制与八种替代，共九场，完整操作与旧版相同；独立公开脚本再成对计算新旧决策，核对 4,939 条指令、3,946 次走棋选择、1,513 次出招选择及完整终态哈希。另检查 106 次完整排序及标准、练习两种难度的 110 次固定随机边界选择。替代前原查询仍照常消耗随机数。
- 隔离本机来源的实际游戏流程包括标准电脑快速局配牌、红兵前进、电脑移炮、查看走棋建议、刷新和继续。恢复后仍为第二回合及相同棋位，建议未执行额外行动；控制台没有警告或错误。没有操作线上旧续局。

## 复核

在仓库中安装 Node.js 后运行：

```sh
node tests/computer-king-scan.cjs
node docs/data/verify-king-query-0.6.119.cjs
```

第二条命令还需要 Git 和包含 `e7c89cdbaccb062e8cbd00f4340dea29bc47aff3` 的仓库历史，用于取得原版入口。也可将待测入口路径和原版 HTML 路径依次作为两个参数。脚本校验原版、修改范围和原公开记录的哈希，完整重算九场；它不重跑所记录的浏览器计时或所有回归脚本。

## 限制

九场复算共用旧起点与八种单步替代，新随机根为零，用于确认行为一致，不作为新增平衡样本。本轮没有重跑完整培养矩阵、真人或实体手机，也没有验证更长的策略搜索。现有协同扫描本身仍只检查将帅空位退路；长局与整体培养平衡仍需继续处理。
