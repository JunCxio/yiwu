本轮减少合法走法查询的候选格数量，保持同一局面的落点、返回顺序、吃子标记和评分。电脑策略、卡牌、伤害、CSS及续局格式不变。不是缩短棋局或调整培养平衡的策略更新。

## 原因与改动

原`moves`对每枚棋子遍历棋盘90格，再调用`canMove`。Node的六份局面、八轮共48次排序剖析得到2,114次CPU采样，`geometry`与`inside`合计1,176次，约56%。这反映该批脚本计算开销，不是网页整体CPU占比。

现在将帅、士、兵只遍历周围一格；马、象遍历周围两格；车炮跳过不在同横线或纵线的格。每个候选仍调用原`canMove`，不复制走法规则。飞将单独补上合法敌将目标，并恢复纵坐标、横坐标升序，防止同分选择或随机选择因数组顺序改变。

该函数供电脑行动、提示、将帅退路和防线检查、棋盘合法落点及无路可走判断共用。没有引入缓存、依赖、存档字段或新的后台任务，原合法性检查、错误处理和支援规则保留。
