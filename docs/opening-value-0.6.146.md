# 0.6.146 首轮可靠吃子的选招收益

标准电脑选择一次可靠首轮吃子时，棋盘评分采用最佳首招的最坏收益，武斗却可能将收益较差的首招混入等概率计划。本版只修正这种偏差：先保留现有将帅安全与省牌结果，再比较真实结束局面的收益。如果原混合计划的最坏期望值低于保留首招中的最好最坏值，只保留达到该值的首招；原混合更优或相等时保持。

比较使用现有评分与十亿分之一的统一精度，不读取玩家暗招。守方、练习电脑、持续交战、残局、棋盘评分、规则、伤害、培养与判和不变。玩家选招建议复用同一入口；没有修改CSS、续局格式或已锁定招式的恢复逻辑。

## 缺陷与定向验证

前置核查重放现版培养矩阵的536份旧记录、173,962条操作，找到870次可靠首轮吃子。其中65次实际混合的保底收益低于棋盘采用的下界，且都仍保留达到下界的首招；758次混合更优，47次相等。因此不能一律去掉随机性。

例如合法记录中，16血黑炮进攻2血红车，斩击和破势均保证存活吃子，但红车使用破阵时，黑炮斩击后剩11血，破势后只剩9血。新计划选择斩击；此前已锁定破势的续局仍按原决定结算，不刷新重抽。

870份状态及红黑旋转共1,740份真实输入，另加7份边界，合计3,494个标准计划、3,494个练习计划与14,522次真实结算通过独立检查。原65处差异及换色得到修正，805处原计划及换色保持；练习计划全部保持。边界覆盖持续交战、第六轮、无伤计数、残局、濒死与将帅目标；输入没有修改，每次实际出招仍只消耗一次随机数。

新增回归附三份完整合法历史前缀：红方差异、黑方差异、混合更优。红黑旋转后的6份输入与40次真实结算通过；原版在首份差异处失败，修正后通过。62份旧专项原样通过，未更新旧断言；143项界面流程通过。

## 新开局对照

试验在结果产生前冻结32组随机流、64个新种子，每组固定配牌与双方随机流，对比原版自弈、候选执红、候选执黑与候选自弈。种子与显式记录的旧种子排重，不声称穷尽全部历史。64场主批通过后，才运行预留64场确认批；128场共享32根，不是128个独立开局。

采用条件为各组直接得分至少8／16，自弈平均行动最多增加10%，每组8场自弈最多多1场和棋。没有事后调整门槛、重抽种子或修改原记录。

## 性能与浏览器

1,740份Node查询，每份5次预热、21次计时，最大中位48.8794毫秒、最大样本70.2513毫秒，通过事前50／100毫秒预算。部分局面增加计算开销；这不是帧率或实体设备测量。

应用内浏览器对三份回归及Node最慢局面的两个阵营版本共5份输入，采用相同预热与采样数量。三份回归候选中位约1.4～2.8毫秒，两个慢局面约38、35.2毫秒；原版相应为35.9、35.5毫秒。候选最大样本46.1毫秒，均通过原预算。测量按原版、候选顺序运行，不据此声称普遍提速。

使用独立8769来源的完整合法历史，核对电脑新开战隐藏暗招、斩击实际结算、结果刷新、旧锁定破势保留、旧结果刷新、红方建议及390像素操作，共8项观察。黑炮新选择剩11血，旧锁定破势剩9血；刷新均仍只有一轮结算。红方建议选择斩击，面对破阵实际剩13血，黑车阵亡。1280×720与390×844流程可完成，窄屏没有横向溢出，正文仍需要滚动；没有页面警告、错误。
