# 普通棋子反杀威胁与查询开销核查

本轮检查普通棋子面对可可靠首轮反杀的来攻时，是否仍因受攻评分反复调子。两份候选通过定向结算核对，但均未通过预先固定的性能门槛，因此没有启动完整对局，也没有采用策略改动。正式游戏、镜像和存档仍为0.6.121。

## 现版行为与范围

现版 `threatCost` 对普通棋子只要存在几何进攻便计入受攻代价；将帅另排除守方能可靠首轮反杀的来攻。这里的可靠反杀要求存在一种守招，面对攻击方全部合法招式都能击倒来攻棋子，并保住守方；它不保证无伤，也不保证战后站位或整局安全。

按真实规则重放两份既有长局的1,100个棋盘状态：478步快速局没有发现这类普通子受攻；622步标准局有25个状态、27次棋子受攻记录，其全部来攻均可可靠反杀。其中7次实际移动把该棋子移出进攻范围。不能据此断定这7次行动错误，更不能把其中一次进攻当作必然更优。

保存前三份完整合法前缀，并做红黑旋转。各份候选分别运行4组定向检查、117次真实结算，核对可靠反杀、无法存活反杀、其他攻击者并存、挑战与将帅原判断，以及查询不修改输入。另有450组招式、气势和支援参数检查：守方使用斩击或破势时，来攻方可用基础反制招把自身损血限制在1；守方架势或蓄势也无法保证造成超过1点损血。因此来攻方高于1血时不可能被保证首轮反杀，可跳过该查询。这是规则参数检查，不是450场对局。

修改只作用于评分及复用评分的走棋、武斗计划和建议。没有改规则、卡牌、伤害、难度、随机采样或持久化字段。

## 两份实现与性能门槛

第一份候选把现有将帅反杀排除扩展至普通棋子，只对1血普通攻击者增加查询，复用完整 `battleOutlook`。44个仓库脚本及143项界面流程脚本共45个脚本通过，未适配或放宽断言。其11个局面的串行计时仍未通过门槛：一个旧局面的中位耗时为原版24.2002、候选53.2582毫秒，候选单次最高101.4198毫秒；标准开局为46.4403、53.2373毫秒。

第二份候选保留相同的反杀条件，针对查询只需要布尔结果的特点逐个枚举合法招式并提前退出，避免计算未使用的交战评分；将帅也使用已验证的1血界限。定向检查通过。11个局面中的上述旧局面为原版12.4969、候选10.0647毫秒，候选最高14.1085毫秒；标准开局为54.0401、54.4094毫秒，仍不满足中位不超过50毫秒的门槛。第二份未继续重跑45个回归脚本。

两批均单独串行运行，交替查询原版和对应候选，各局面预热2次、记录11次。原版在两批中的耗时也有变化，因此不能把候选53→10毫秒直接当成稳定提速结论。门槛始终为：各局面中位不超过50毫秒、单次不超过100毫秒，开局额外中位不超过5毫秒。原版在第二批也超过绝对门槛，没有因此放宽条件或反复测至通过。这些是本机Node.js计时，不是浏览器、帧率或手机结果。

## 独立复核与限制

在仓库目录运行：

```sh
node docs/data/verify-counter-threat-0.6.121.cjs
```

后续版本可将本报告指定的0.6.121入口路径作为第一个参数。脚本核对来源、两份补丁、规则与界面不变，重新计算1,100个历史棋盘状态及两份候选各117次定向结算、450组界限检查，检查回归日志、原始计时汇总、种子与未采用结论。已实际运行通过，错误的0.6.120入口在来源检查处被拒绝。复核不会重跑45个回归脚本或计时，也不会启动预留的136场对局。

本轮只补诊断与公开证据，没有发布策略候选，没有做候选浏览器、实体手机、完整培养矩阵或真人测试。反杀可能付出生命或培养牌，不能将取消威胁评分视为已证明正确的策略；整体平衡、单子主导和长局问题仍需处理。
