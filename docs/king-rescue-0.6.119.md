# 将帅友军解围与对局节奏试验

本轮尝试让电脑区分“将帅没有安全移步，但友军仍能解围”和“非交战移动、整备都不能解围”。候选通过定向与回归检查，但136场完整对照没有达到原定采用条件，因此不发布这份策略。正式入口、本机镜像与版本保持0.6.119。

[完整计划、两份候选补丁、失败检查、性能样本与全部操作](data/king-rescue-0.6.119.json)，SHA256：`cc71d42101a882098e4992e3f5069672966646492396df39dbdf73e3af9cbae5`。来源提交为 `a6d170a955aab7de1561678f15d4e30b8b56782e`，正式入口SHA256为 `50f17297fab23c497358f6cf716c9d4da6930d6befb8609297441d153c56c272`。另有[独立复核脚本](data/verify-king-rescue-0.6.119.cjs)。

## 评分问题与修改范围

现版通过 `rankedActions → position → kingMobilityCost → advanceTrapsKing` 评估未来压力。对手一次调子后，若将帅受攻且没有安全空位退路，统一扣4.2分；这个查询没有继续区分友军能否挡线或整备解围。

候选将内部布尔查询改为 `kingAdvanceCost` 数值查询，在原有0.6.119几何预筛、真实走法、可靠反杀、判和和将帅退路检查后，枚举友军非交战移动及本方整备。仍能解除受攻时保留4.2分；不能时增加既有的延后威胁代价。健康且无支援的典型情况为8.4分，实际值仍使用现有生命与支援计算，没有增加可调参数。

该判断没有推演完整获利反击，不能称为将死或必败。普通交战后的将帅风险及 `twoRoundCapturePlan` 也复用这部分评分，因此走棋排序、武斗选招与对应建议都可能变化。规则、卡牌、生命与伤害、界面、随机采样代码和存档格式均未改变，没有新增持久化字段或异常分支。候选只保存在实验补丁中，没有写入正式入口或续局。

## 第一份候选与测试修订

第一份候选在无法非交战解围时，直接使用未来受攻局面的完整当前风险，健康无支援时为42分。它通过定向与性能检查，但 `computer-initiative.cjs` 发现：把未来调子压力与当前已经受攻等价扣分，可能让仍留下眼前威胁的行动得分更高。第23次行动的诊断中，安全移将后当前风险为零、未来风险42；危险移将当前风险42，前者的排序得分反而更低。完整诊断保留在公开数据中。

`computer-king-zero-exit.cjs` 也失败，但它原来要求两个都有逼帅分支的落点评分相等。独立枚举发现，原字段中的安全落点仍可由友军解围，另一个落点含无法非交战解围的分支。第二份候选因此保留全部逼帅、可靠反杀、判和、红黑旋转和输入隔离检查，新增真实解围枚举，将“评分相等”改为“可解围落点更优”。这是一项明确的测试语义修订，不能描述为所有旧断言逐字未改。

第二份候选采用较低的既有延后威胁权重，原眼前避险断言恢复通过；没有在完整对局进行中调参。第一份未启动完整对局，其预留的64个种子仍加入排除集合。公开数据保留第一份补丁、失败日志和诊断，没有把未运行的计划计为样本。

43个仓库脚本及143项界面流程脚本共44个脚本通过，其中五个测试仅适配内部查询注入接口，零退路测试另有上述语义修订。定向测试按真实规则重放一份旧拒绝候选中的合法历史及红黑旋转，独立枚举40条非交战回应，确认4.2与8.4的区别及优先仕挡线；还检查两种难度的固定随机边界和输入不变。这份历史不是现版自然自弈，也不是新增平衡样本。

## 固定计划与结果

第二份候选冻结后运行136场：32个新根各运行原版双方、候选执红、候选执黑和候选双方，共128场；另4份旧记录分别运行原版双方和候选双方，共8场。新根覆盖标准、练习两种难度和快速、完整两种棋局，两批配牌包括默认、分散、进攻、防守、混合方案。双方预算相等，每子最多两张培养牌。

64个新种子与3,244个已记录或预留值无重合，标签为 `yiwu-king-rescue-0.6.119:20261112:deferred`；排除集合包含第一份候选未使用的预留值，不能全部称为已采样历史。换色对战、自弈和旧控制相互关联，136场不等于136个独立样本。

原定门槛要求每种难度与棋局的直接对战至少半分，自弈平均及最长行动都不增加；全部通过后仍需独立新根复测。没有因结果修改门槛。

四份旧控制精确复现166、318、478、622次行动；候选分别为222、149、285、622次。第一份仍黑胜，第二份由和棋变为红胜，后两份仍和。旧病例改善不代替新根筛选，标准622次长局也未缩短。

## 性能与复核

完整对局前，单独串行测量11个开局及旧局面，原版与候选交替运行。所有局面满足原有中位不超过50毫秒、单次不超过100毫秒、开局额外中位不超过5毫秒的门槛。标准开局中位46.7595→49.1561毫秒，候选最高56.6755毫秒；定向解围局面中位13.786→25.9561毫秒，最高29.2302毫秒。通过门槛不代表提速，不能将Node.js计时当作浏览器、帧率或手机结论。

在仓库目录运行：

```sh
node docs/data/verify-king-rescue-0.6.119.cjs
```

游戏后续更新后，将报告指定的0.6.119入口路径作为第一个参数。脚本检查数据、来源与两份补丁哈希，确认规则与界面脚本逐字不变，核对完整计划、种子排除、旧控制和采用结论，再分四个独立进程重算全部136场的走棋、出招及随机流。实际配牌、45,788条规则指令、34,499次走棋选择、16,749次出招选择、8,156轮交战、逐子损血、耗牌、阵亡、往返行动及完整终态均核对。

可使用 `node docs/data/verify-king-rescue-0.6.119.cjs index.html 0` 单独复核一个分片，最后的数字可取0至3；每片34场。默认运行还重做40条定向解围枚举。复核脚本不重新运行所记录的44个回归脚本、第一份候选诊断或性能测量，仅检查其记录和数值汇总。

上述默认命令已实际执行通过，全部选择、逐子统计与终态哈希一致；错误版本入口在来源哈希检查处被拒绝。

## 限制与正式版本

候选没有通过主试验，因此不执行独立采用复测、候选浏览器验收或更多调参试验。没有重跑全部合法配牌矩阵、真人或实体手机测试。正式策略保持0.6.119；友军解围的局部评分问题已得到更细的诊断，但整体强度、长局和集中培养问题仍不能视为解决。
