# 近路目标与单步替代核查

继续核查[未采用的静态路线候选](piece-route-trial-0.6.136.md)。在主批和独立批的全部首次分歧中，有近半近路的最短端点全部通向现版评分为负的交战。对全部16份变化自弈各做一次走法替代后，负分端点组有3个结果变差；另一组仍有2局变长。结果不支持仅补一个正分过滤便采用路线策略，正式游戏、版本、规则和存档保持0.6.136。

正式入口SHA256为 `812c41ee1b1edbe63fb2b930ec1593ca89123b65edfb816131fa2ddd40e4fe16`。本轮[完整诊断、冻结分支、操作、脚本与日志](data/route-value-audit-0.6.136.json.gz)为gzip压缩JSON，SHA256为 `6f624bbd70974fa58089ba1a7890c65bca7d875c32e83f5a43c19666cdd6c101`。原版、失败候选与全部旧对照仍在[上一轮数据](data/piece-route-trial-0.6.136.json.gz)，本轮不覆盖旧结果。

## 首次分歧的目标

逐一检查上一轮修正版主批和独立批中全部192份候选参与记录，与各自同根原版控制比较，得到33份首次分歧，分别为17、16份。其中各有8份候选自弈；同根换色对战可能出现相同状态，这33份不是33个独立起点。

每处首次分歧都是同一枚棋子的同分空位走法。原版与候选走法分别按真实规则执行一次，再固定其他棋子，搜索到任意合法进攻入口的最少空位移动数。对所有最短端点重新运行现版完整走棋评分，列出每个可交战目标、生命、首轮终结与反杀信息；不是只看距离或首轮交换。静态投影没有实际推进对手的回合，不能把这些端点当作真实未来局面。

| 原批次 | 首次分歧 | 候选最短端点全部交战负分 | 原版最短端点全部交战负分 | 候选新增直接来攻 | 候选下一手三轮确定丢将 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 主批 | 17 | 8 | 5 | 0 | 0 |
| 独立批 | 16 | 8 | 6 | 0 | 0 |

“新增直接来攻”为该处可直接进攻移动子的敌方选项数较原走法增加，不表示完全没有敌方攻击；“三轮确定丢将”只覆盖现有下一手查询。这批首次分歧未发现这两类新增风险，不能据此称路线全程安全。

一份独立标准快速局的黑兵，近路距离由5降为4，但最短端点的最大进攻评分从76.45降为−30.2：原较远入口是红帅，近路入口是红仕。另一份独立标准完整局的黑马，原落点在固定棋子下没有进攻路线，候选落点一步即可进入交战，但两个最短端点的攻击评分分别为−0.7、−4.275。它们说明“更早能打”没有包含“是否值得打”。现有评分本身仍有平均伤害等估算限制，负分也不是该交战实际必败的证明。

## 只替换一次走法

在分支开始前冻结全部16份变化自弈，不按好坏挑选。每份运行原版控制和一次替代，共32场；替代只在首次分歧处执行候选走法，此后双方全部恢复现版电脑，沿用原来的双方随机流。控制的全部命令与终态须精确复现旧控制，替代须精确保持之前的命令。仍要求自然终局，超限算失败。

全部32场、12,172条操作重放一致，16份控制的全部命令及终态与旧记录相同。这是旧输入的干预分支，不是32个独立新根或新策略采用验证。

| 候选最短端点评分 | 案例 | 行动方结果改善／变差 | 更短／更长／等长 | 首次目标在对手回应后变化 |
| --- | ---: | ---: | ---: | ---: |
| 至少一个交战非负 | 8 | 0／0 | 5／2／1 | 1 |
| 所有交战均负 | 8 | 0／3 | 3／2／3 | 0 |

“结果”按替代行动方计胜1、和0.5、负0。所有交战负分组有两处由和棋变负、一处由胜变和。其3个变短案例中包含2处输棋，不能把行动数减少全部视作节奏改善。另一组8处原局和分支均和棋，最短端点都是正分；其中练习快速的一份由237增至367次行动，另一份由250增至279次，说明仅排除负分端点也不足以证明通用改善。

15份单步替代的全部命令与此前持续使用候选的记录相同；独立标准快速一份仅替代一次仍300次行动和棋，持续使用候选则350次行动和棋。这里核对的是完整操作相同，不只是终态相同。

另外逐步重放每份分支中对手的第一次实际回应，包含完整武斗结算，再重新核对移动子的静态路线。仅1份最短入口的目标改变位置；另有目标不动、其他棋子移动使距离从1增至2的情况。目标不移动也不能保证路线或收益稳定。原路线选择没有维持多步目标，后续现版电脑也可能改走其他棋子；本轮没有把静态最短路线当作实际执行计划。

## 独立复核与限制

在仓库目录运行：

```sh
node docs/data/verify-route-value-audit-0.6.136.cjs
```

脚本仅依赖Node标准库，需要本轮和上一轮两份压缩数据。它核对哈希及全部192份候选记录的首次分歧，通过完整90格有向图独立重算两种走法的最短距离、所有最短端点及现版评分，再核对直接来攻和将帅风险。之后重放32场、12,172条操作，复算控制一致性、首次替代、分组结果、与持续候选的完整命令比较、对手实际首个回应及回应后的路线。

脚本不重算分支中的全部电脑决策，也不重新生成随机完整对局。后续入口发生变化时，须传入本报告指定哈希的0.6.136入口路径。本轮不修改正式旧测试，未进行新策略独立采用复测、完整培养矩阵、浏览器、刷新续局、真人或实体手机测试，也不宣称整体强度、节奏或培养平衡改善。

下一步应核对对手回应后的可兑现收益与后续行动选择，先证明局部方案有价值并满足查询耗时，再开展独立完整对照。不能根据这16份分支调一个过滤阈值，然后复用同一批结果称为独立验证。
