# 0.6.99 武斗结束后的将帅防线

2026-11-11，修正普通棋子武斗选招只比较当轮损血、忽略离场后将帅受攻的问题。标准电脑与「选招建议」共用修正；不读取暗招，不改变伤害、卡牌或走法。

[固定计划、完整操作与验证数据](data/combat-line-0.6.99.json)包含 98 局与 22,660 条指令。正式入口及镜像 SHA256 为 `e69032807de1a0824915a807c600a91757b07ea6da5222fc0e39903ba5782fa1`，数据 SHA256 为 `66a0fb44995b127a62480b950890031b22aba7ff5e953f14634dff8fe6485330`。对照原版为 0.6.98，源码提交 `fb36dc8f54da20414bf3d0f0f94cd733eac554a2`，入口 SHA256 为 `58eb2c50c323e8841e7d8422c3a739dfac6a325c913f5ad5440a3538f8f2f75c`。

## 复现与修改

病例来自 [0.6.98 培养矩阵](balance-0.6.98.md)：快速局第 11 次行动红炮进攻黑炮，第五轮红炮剩 4 血、黑炮剩 7 血。原版仍给「斩击」分配概率；遇到黑方「架势」时红炮阵亡，黑炮可隔红马进攻红帅，下一行动最终取胜。红帅当时满血，这只是新增受攻，不能误称黑炮能确保两轮取胜。

现在双方均为普通棋子且不是残局时，对进攻方所有可用招式与撤回，枚举守方全部合法回应。只有本轮实际结束交战的分支才按规则结算生命、耗牌、占位、重复局面及胜负：先比较是否留下对手下一手首轮确定取将，再比较两轮确定取将，最后比较将帅受攻代价是否高于当前。使用原有受攻检查，首轮可确保存活反杀的进攻不算有效威胁。真实终局不再虚构下一手；所有选项风险相同时仍保留合法计划。

有更安全替代时，进攻方只在风险较低的招式中比较当轮收益；守方的混合策略也按这组公开可用的进攻选择计算。将帅自身出战、确定胜局及残局沿用原有逻辑，基础招式与培养牌仍由玩家自由选择。练习电脑的类型随机、走棋评分及开战前的普通战斗平均伤害估算保持原样。保存中已锁定的电脑招式继续保留，之后的新轮次使用新决策。

## 旧病例与新起点对照

先固定 17 场单子输出胜局的原版与候选复跑，再固定两批各 32 局默认配牌对照。每批快速、标准各四组随机根，每组原版自弈、交换红黑的两局直接对战与候选自弈。随机标签为 `yiwu-combat-line-20261111:{batch}:{scenario}:{replicate}:{side}`，SHA256 前四字节按小端读取，使用现有 32 位线性同余序列。32 个新起点与 0.6.98 培养矩阵及前轮默认对照不重合；同根的四场相关，不能把 64 场视为独立样本。

所有 98 局自然结束，600 次棋盘行动与 4200 内部步骤的错误保护未触发。完整指令重放、预算、每子两牌上限、终局哈希、阵亡、耗牌及逐子实际损血一致。

## 性能与剩余问题

54 个真实武斗状态，预热两遍后新旧交替各七遍、双方各查询一次，每版 756 次 Node 查询。平均耗时约 1.665 → 2.376 毫秒，P95 3.545 → 6.136 毫秒；输入未变。只代表本机 Node 测量，没有实体设备或浏览器性能结论。

开战前平均伤害预测仍会遗漏后续阵亡，武斗中也只检查本轮离场后的下一手风险，不搜索完整六轮或更长走棋。没有做新版完整培养矩阵、真人策略或全部配牌穷举；单子输出胜局、长局、红黑差异与集中培养仍需继续验证，不能认定已解决整体平衡。
