# 0.6.131 武斗选中状态与键盘焦点

原版将已选牌和键盘焦点都画为外框；已选样式还会覆盖键盘焦点。真实Edge中，已选斩击牌聚焦与失焦都显示相同的2像素外框，牌面也没有选中文字，难以判断键盘位置。

现在已选牌使用2像素的牌内描边，并在原有说明行显示「已选」。键盘仍使用全局3像素外侧焦点框。焦点移走后保留选中描边，只有明确锁定才结算。基础与培养牌均直接读取原有 `pending`，继续保留 `aria-pressed`；没有新增状态或保存字段。同机交接不显示上一方的选牌标记。

## 验证

[证据摘要](data/combat-choice-state-0.6.131.json)包含原版焦点样式、最终源码哈希和浏览器结果。新增检查仅依赖Node.js内置模块，在仓库目录运行：

```sh
node tests/combat-choice-state.cjs
```

- 4组专项：基础和培养牌反复换招，标记与待选保持一致；同机交接隐藏、守方独立选择与下一轮清空；建议和教学；现有存档格式的刷新重建。选招不改变规则状态，不重抽电脑暗招；只有锁定才结算。原版先在斩击缺少标记的断言失败。
- 143项既有界面流程、9组待保存续局、既有残局流程及4组武斗确认导航检查原样通过。旧脚本与断言未改。
- Edge在1366×768、1024×640、390×844、320×568、760×480分别检查电脑与同机，共10个流程、80次选择状态核对。实际键盘Enter选招、Tab移开与返回后，外侧焦点改变、内侧选中描边保留；文字完整位于牌内，没有横向溢出或页面错误。
- 每个浏览器流程选择六种招式，再核对失焦和刷新：命令与电脑暗招保留；同机交接隐藏标记，守方选择独立；双方锁定后仅追加一次真实结算。已查看桌面、320像素及短横屏截图。

规则、电脑脚本与0.6.130逐字相同；CSS仅替换已选牌的描边实现，没有更改首页、棋盘、武斗的布局或滚动策略。培养、伤害与存档格式1保持，本机镜像与发布入口一致。

未重复不受影响的完整规则／电脑回归、培养矩阵或性能基准。未做独立真人、实体手机、屏幕阅读器、其他浏览器和系统高对比度验收。本轮不改变整体强度或平衡，单子主导、长局和高和棋比例仍需处理。
